# 5주차 학습내용

  ## 1. 객체 지향과 SOLID 원칙

    ### 객체 지향 프로그래밍(OOP)

        프로그램을 명령어의 목록이 아닌 여러 객체들의 조립으로 보는 패러다임

        + 추상화 : 객체의 공통적인 속성과 기능을 추출하여 정의

        + 캡슐화 : 서로 연관있는 속성과 기능들을 하나의 캡슐로 만들어 외부로부터 보호

        + 상속 : 기존 클래스 속성 및 기능을 새로운 클래스가 물려받아 재사용

        + 다형성 : 객체의 속성 및 기능이 상황에 따라 여러 가지 형태를 띨 수 있는 것

        + 다형성은 역할과 구현을 분리하여 클라이언트 코드 변경없이 구현체를 교체할 수 있게 해줌


    ### SOLID 원칙

       + SRP(단일 책임 원칙): 하나의 클래스는 하나의 책임만.
       
       + OCP(개방-폐쇄 원칙): 확장에는 열려 있으나 변경에는 닫혀 있게.

       + LSP(리스코프 치환 원칙): 자식 클래스는 부모 클래스를 대체할 수 있어야 함.

       + ISP(인터페이스 분리 원칙): 인터페이스는 목적에 맞게 잘게 쪼개야 함.

       + DIP(의존관계 역전 원칙): 구체적인 것이 아닌 추상화(인터페이스)에 의존해야함. 
    


  ## 2. 스프링의 핵심 개념

    ### IoC(제어의 역전)
    
     객체의 생성과 관리의 제어권을 개발자가 아닌 프레임워크가 가져가는 것

     스프링 컨테이너가 객체(빈) 관리


    ### 스프링 컨테이너와 빈

     객체를 싱글톤 패턴으로 관리하여, 애플리케이션 전반에서 하나의 인스턴스만 생성해 재사용


    ### 의존성 주입

     객체가 필요한 의존성을 직접 생성하는 것이 아니라 스프링 컨테이너에서 주입받는 방식

     클래스 간의 결합도는 낮추고 유연한 설계 가능
    


  ## 3. 리팩토링 실습

    ### 빈 등록 방법
    
     수동 등록: @Configuration과 @Bean 어노테이션으로 직접 등록

     자동 등록: @Component 어노테이션으로 스프링이 자동으로 빈으로 등록
    

    ### 의존성 주입 방식
    
     생정자 주입: 객체 생성 시점에 의존성을 주입 받고, 불변성 보장 및 누락 방지 가능

     + 수정자 주입, 필드 주입
